# flymath — 数学符号扩散特效生成器

一个纯前端的网页小工具：**上传一张图，让数学符号从画面中心向四周飞散扩散**，导出 PNG 或 GIF。

这个仓库收录的是同一个需求交给不同 AI 编码工具后拿到的 **13 份实现**，按模型来源分成两个目录。它们不是迭代关系，而是同一句话的 13 种理解 —— 每一版坏掉的方式都不一样。

> 零构建、零后端。绝大多数版本是单文件 HTML，双击即可打开（联网加载 CDN 依赖）。

## 怎么用

1. 打开任意一个 `.html`（见下表）。
2. 选一张背景图。
3. 调参数（飞行速度 / 消失半径 / 字号 / 变大速度）。
4. 导出 PNG 或 2〜3 秒的 GIF。

```bash
# 或者直接起个静态服务
python -m http.server 8000
# 访问 http://localhost:8000/overseas/mathflay-grok.html
```

## 我修掉的两个真实缺陷

收录前逐个核对了所有外部引用（无一处写了 SRI `integrity`，所以不存在哈希对不上的问题），发现 2 个失效 URL：

**1. `mathflay-grok.html` 的 GIF 导出必然失败。**
它把 worker 指向 `https://cdn.jsdelivr.net/npm/gif.js@0.2.0/gif.worker.js` —— 这个路径不存在。`gif.js` 在 jsdelivr 上的 worker 实际在 `dist/` 下。已改为 `.../gif.js@0.2.0/dist/gif.worker.js`。

判据（在页面自己的源下取回，不是离线 curl）：

```
修正后 URL → 200，16,636 字节，正文开头 "// gif.worker.js 0.2.0 - https://github."
修正前 URL → 404
```

**2. `mathflay-gpt-mirror.html` 加载了一个不存在的依赖。**
`https://cdn.jsdelivr.net/npm/@ninjadev/image-to-base64` 返回 404，而且**全文没有任何一处引用它** —— 只有那行 `<script src>`。属于模型顺手编的依赖。已删除该行。

判据：修复后在浏览器里加载该页，`window.GIF` 与 `window.html2canvas` 均为 `function`，页面有 3 个按钮（开始动画 / 导出截图 / 导出 GIF）；喂入一张 640×400 测试图并点击开始后，1280×800 画布的 103 个等距采样点**全部非透明**，即背景图与特效确实绘制出来了。

> 说明：本机内嵌浏览器初始视口是 0×0，而这一版把画布尺寸绑在 `window.innerWidth` 上，所以必须先把视口设为 1280×800 才能测 —— 这是测试环境的问题，不是这份代码的缺陷，但**它确实意味着视口为 0 时画布就是 0**（缺一个尺寸兜底）。

## 关于两个 `.tsx`

`math-explosion-claude.tsx` 和 `mathflay-claude-mirror.tsx` 是 React 组件。后者原本以 `.html` 为扩展名躺在目录里 —— 但它没有 `<!DOCTYPE>`、没有 `<body>`，开头是 `import React, { useState, ... } from 'react'`，全文 45 处 JSX/React 标记。**双击它不会打开任何东西**，只会让人以为这个工具坏了。我按实际内容把它改名为 `.tsx`。

两份都需要接一个 React 构建环境才能跑，本仓库不含构建配置。

## 命名说明

`overseas/` 与 `domestic/` 的归属依据是**文件名与文件内自述**：`overseas/` 里各文件标题带 Gemini / Claude / GPT / Grok；`domestic/mathfx-glm47.html` 页脚写着 `Generated by GLM4.7`，`mathfx-qwen.html` 来自 Qwen 的输出文件名。`mathfx-unknown.html` 找不到任何署名线索，故保留原名语义。

我没有当时的原始 prompt 记录，因此**不声称这些是同一句 prompt 的产物** —— 只能说它们是同一需求下的多模型产物。
